# DictionForge GPT-SoVITS v4 微调项目阶段实施计划

项目中文名为 **声句工坊**。独立仓库及默认本地目录使用 `DictionForge`，Python 包使用 `dictionforge`。规划日期为 2026 年 11 月 17 日。

项目使用用户已创建的 GitHub 远端。HTTPS 克隆地址为 `https://github.com/xdmiemie/DictionForge.git`，认证沿用用户现有方式。[xdmiemie/DictionForge](https://github.com/xdmiemie/DictionForge)

交付一套本地运行的中文 WebUI。用户选中一堆角色录音所在的目录，完成语音切分、转写、校对和训练特征准备，再微调 GPT-SoVITS v4。导出模型后，用户选择音色并输入文字即可合成语音、试听和保存。满意的一句可以直接加入该角色的训练数据，生成新数据版本并继续微调。

首发按 TimbreForge 的 Windows 11、RTX 5080 16 GB、32 GB 内存环境规划，使用单机单 GPU。本计划以 TimbreForge 的阶段文档、现行使用手册和源码作为操作基准。[TimbreForge 阶段计划](docs/PROJECT_PLAN.md) · [现行使用手册](docs/USER_GUIDE.md) · [训练与推理界面](frontend/src/main.tsx) · [数据追加实现](backend/timbreforge/augmentation.py)

## 0 阶段执行约定

1. 实施时将指定远端克隆到与 TimbreForge 同级的 `DictionForge` 工作区，按 P00–P12 推进。每阶段记录交付项、真实运行命令、结果、阻塞项和后续工作到新仓库的 `docs/CODEX_PROGRESS.md`。状态使用 `NOT_STARTED`、`IN_PROGRESS`、`BLOCKED`、`DONE`。
2. 使用固定的上游源码、可重放的补丁和模型资产清单。运行配置与实际生效参数一同归档。目标机器上的批大小、精度、显存占用和音质用实测结果填写。
3. 以真实录音或有明确文本的短音频夹具通过 GPU 端到端验收。角色效果用用户提供的角色录音单独试听。数据、模型、检查点、日志和作品写入应用数据根目录，Git 跟踪源码、锁定文件、测试和文档。
4. P00–P12 各做一次本地 Git 提交。每个阶段通过验收并更新 `docs/CODEX_PROGRESS.md` 后，将该阶段的交付物与验收记录一并提交，提交信息以阶段编号开头，再开始下一阶段。
5. 全部阶段验收完成且 P12 的本地提交落盘后，才尝试将实施分支推送至 `xdmiemie/DictionForge`。推送后核对远端分支的提交哈希。若推送失败，保留全部本地提交并记录失败原因。

## 1 界面和功能范围

WebUI 保留两个主标签 **微调训练** 和 **语音合成**。共用后台任务区、日志、环境诊断与资产准备入口。项目的推理业务以本地参考音频和用户文本为输入，输出单条 TTS 语音。合成结果回流使用整句选择。

| 界面 | 首发操作与反馈 |
| --- | --- |
| 录音数据 | 浏览服务电脑或粘贴目录，填写角色和语言，选择是否扫描子目录。扫描后展示有效时长、排除原因、文件试听和排除勾选。点击「整理数据集」执行切分、ASR 和质量检查，展示逐段音频和转写，支持修改文本、语言和排除项。 |
| 训练配置 | 选择数据版本、准备或补齐特征、选择初始化权重、配置 GPT 和 SoVITS 两阶段、检查训练配置与显存，再点击「开始训练」。回流版本可预选合成来源模型，也可切回官方底模。 |
| 后台任务 | 浏览任务列表、真实进度和日志。支持取消、暂停并保存、继续训练、导出并继续、提前中止并导出、完成自动导出、从历史恢复点派生，以及从同一快照重试失败的导出。 |
| 模型效果测试 | 选模型版本，使用相同的测试短句、参考音频、参考文本、语言和种子生成试听。支持并排播放基线与候选结果，并显示各自实际参数。 |
| 模型与数据集管理 | 查看角色、版本、阶段进度、片段和时长。支持删除指定发布版本或数据版本。活跃任务、有效恢复点、默认参考及派生版本所依赖的文件受引用保护。删除范围以确认框显示。 |
| 语音合成 | 选择自训模型或导入兼容的 GPT 与 SoVITS 权重对，开启模型，使用该版本保存的参考素材或更换参考。输入文本并生成，显示当前句子、播放器、实际生成参数和错误。 |

| 已保存语音 | 播放和下载，按模型、标题或文本筛选，每页最多 10 条。支持删除单条、全选本页或选中全部筛选结果批量删除。 |

每个角色可以保存多个数据与模型版本。语音合成页开启模型后，用户日常只需填写目标文本。默认参考素材随模型版本登记，可试听并查看对应文本与语言。

## 2 应用架构与目录

沿用 FastAPI、Pydantic、React、TypeScript、Vite、SQLite 和 SSE。API 管理配置、版本和任务，独立 worker 执行特征提取、训练、模型检查与推理。划分 API、GPT-SoVITS 与 ASR 运行环境，依赖经验证可共存时允许共用 worker 环境。CPU 数据任务可以与 GPU 训练并行，GPU ASR、特征、训练和推理由同一监督器串行调度。

服务默认绑定本机 `127.0.0.1:7867`，端口可配置，以便和 TimbreForge 同时启动。使用 Windows 原生目录选择和服务端路径文本框，两者都须支持盘符、中文和空格。GPU worker 进程退出后确认进程树和显存释放。两个应用同时运行时，预检读取实际可用显存，显示占用详情并处理 OOM。

| 路径 | 职责 |
| --- | --- |
| `backend/dictionforge/` | 任务监督、数据清单、ASR、特征、训练控制、模型发布、TTS、产物和追加服务。GPT-SoVITS 特有逻辑放入适配层。 |
| `frontend/src/` | 两个主标签及共享的路径、播放、进度、模型、数据与作品管理组件。 |
| `configs/`、`vendor/gpt-sovits/`、`patches/gpt-sovits/` | 默认参数、版本与资产锁、固定源码获取方式和可重放补丁。 |
| `scripts/`、`启动DictionForge.cmd` | 资产准备、安装、诊断、启动和停止。重复启动打开现有服务。 |
| `data/assets/`、`data/datasets/<id>/<version>/` | 底模及依赖资产、整理音频、标注、清单与训练特征。 |

### 2.2 GPU 租约、环境探测与诊断

- 训练预检、GPU 特征、GPU ASR、训练、试听与合成共用排他租约。worker 将运行 ID、PID、启动时间和租约令牌交给监督器。重启时结合这些信息核对进程身份和最近有效产物，再恢复或标记中断。
- 模型逻辑开启与 GPU 驻留分别显示。训练开始前卸载闲置推理实例。切换模型使用新权重和参考条件重建缓存，已受理任务按自己的快照完成。关闭合成入口后，已受理任务仍可通过后台任务显式取消。
- 启动探针记录驱动、CUDA、Torch、设备、可用显存、CPU 内存和各目录空间。CUDA 预检实际执行小张量运算，诊断结束后退出探针进程。训练 OOM 显示阶段、设备及请求参数，重新提交时再次检查资源。
- 资产支持下载和从本机文件导入。下载写入临时路径，校验通过后替换目标文件。`doctor.ps1` 检查依赖版本、资产哈希、缓存路径、单实例锁和本机回环访问，能区分缺文件、版本错误与 GPU 不可用。

## 3 GPT-SoVITS v4 资产与配置

| 配置区 | 字段和约束 |
| --- | --- |

| SoVITS | v4 官方 LoRA 路线，使用 `s2_train_v3_lora.py` 的 v4 分支。显示 LoRA rank、物理 batch、总轮次、学习率、精度和已接通的显存选项。rank 初值 32，batch 与其他训练默认值由锁定上游配置和实机预检确定。 |
| GPT | 使用 `s1_train.py`，独立配置 batch、总轮次、精度、保存周期与已验证的高级设置。上游配置存在的开关只有在端到端接通后才进入 UI。 |

| 推理基础 | 目标文本、目标语言、断句方式与语速。建议初值为语速 1.0、推理 batch 1、`sample_steps=32`，运行记录同时保存实际值。 |
| 推理高级 | `top_k`、`top_p`、`temperature`、`repetition_penalty`、种子、断句间隔和已验证的采样选项。按 v4 加载器实际支持组合校验。 |

## 4 从原始录音到训练数据

1. **扫描检测。** 只读递归枚举录音，探测格式与完整性。接受 FFmpeg 能解码且已纳入测试的 WAV、FLAC、MP3 等输入。记录源哈希、声道、采样率、时长，报告损坏、静音、重复和手动排除项。提供可试听的扫描结果。
2. **整理数据集。** 解码并生成工作副本，按语音停顿和长度切分，处理过短、过长、静音和削波片段，按需要调整音量。保存切片与源文件的时间区间。普通话优先接入上游 FunASR，其他首发语言接入已实测的 Faster-Whisper 识别设置，并分别记录 ASR、训练和推理支持的语言。整理页面展示进度、识别失败、可用时长和待校对数量。[上游切分、ASR 与校对流程](https://github.com/RVC-Boss/GPT-SoVITS/blob/20250422v4/README.md#finetune)
3. **校对并发布版本。** 每段逐条试听、编辑转写和语言，允许剔除。确认后生成不可变清单和 UTF-8 `.list`，格式为 `音频路径|说话人|语言|文本`。校验分隔符、空白文本、语言代码与文件可读性。以原始录音为组划分训练和验证。同组片段及重复音频只进入其中一边。验证集用于留出试听，验证 loss 在接通有效验证循环后展示。
4. **准备训练特征。** 按上游顺序生成文本音素和适用的 BERT 特征、CN-HuBERT 音频特征及 SoVITS 语义 token。验证文本索引、声学特征、音频与语义表中的键一致，再用实际 S1、S2 加载器读取。以音频哈希、校对文本、语言、处理配置和资产版本建立缓存键，补跑只重建失效或缺失项。失败时保留已确认的标注和可复用缓存。[上游特征任务编排](https://github.com/RVC-Boss/GPT-SoVITS/blob/20250422v4/webui.py)

版本清单记录数据集 ID、版本 ID、父版本、来源和分组、片段 ID、音频哈希、标注来源、处理参数、训练或验证归属、保留时长及 fingerprint。特征就绪状态单独跟踪。训练绑定冻结的数据和配置，校对后再修改会生成新版本。

### 4.1 目录扫描与时长统计

- 源目录保留在清单中，生成物统一使用数据根目录中的稳定 ID。扫描报告按文件列出可解码、保留、排除时长及原因。以样本数和实际采样率计算切片时长，预留的音频重叠区间按并集计算保留时长。
- 切分设置保存静音阈值、最短停顿、片段最小和最大时长及边界留白。阈值在 P03 按锁定工具与样本测试确定。片段过长时优先找下一处可切停顿。过短、空音频和重复样本在报告中可定位。
- 同一源录音的相邻切片、解码重复和可识别的同源复制绑定到同一组。按组生成稳定的训练、验证划分。仅有一组时报告留出试听不可用，提示增加真实来源或使用经标识的外部试听样例。训练可用性按真实加载器和产品配置预检。

### 4.2 ASR 草稿和文本审核

草稿保留每段的转写来源、语言、处理时长、审核状态和原始候选。校对页按文件分组并支持「只看待处理」，点片段播放后可编辑文本、确认或排除。ASR 失败的片段可单独重试，手工校对过的条目保持其编辑内容。正常录音目录只需要音频即可开始；已有准确文本时，允许在草稿中录入或用可校验的对应表填充。

写入 `.list` 前校验每行恰好四个字段。对正文中的竖线和换行按明确规则规范化并保留原文本，界面显示最终训练标注。采样文件使用唯一 basename，避免上游以 basename 作为特征键时合并不同源文件。适用语言由 ASR、训练文本前端和推理能力分别公开，无法识别或不支持的片段要在发布前得到明确处理。[上游文本解析和文件键](https://github.com/RVC-Boss/GPT-SoVITS/blob/20250422v4/GPT_SoVITS/prepare_datasets/1-get-text.py)

### 4.3 特征产物与失效规则

| 处理阶段 | 入口与产物 | 依赖校验 |
| --- | --- | --- |
| 文本与 BERT | `1-get-text.py` 生成 `2-name2text.txt`，适用条目生成 `3-bert/` | 文本、语言、前端规则及 BERT 资产版本，校验音素和 BERT 时间维对应 |
| 音频与 SSL | `2-get-hubert-wav32k.py`，生成加载器所需音频副本与 SSL 特征 | PCM 哈希、重采样参数、CN-HuBERT 资产及设备精度，校验形状和时长 |
| 语义特征 | `3-get-semantic.py`，合并 `6-name2semantic.tsv` | SSL 特征、语义提取器、模型配置及锁定权重哈希，校验条目和 token 维度 |
| 加载器检查 | 构造两个阶段的实际输入视图 | 同一条片段各产物键能对齐，分组和验证排除在训练视图中生效 |

一次补跑可以重建聚合索引并复用其中的有效特征。改转写优先失效文本侧，音频或 SSL 变更按依赖重新生成语义侧。上游脚本退出后对预期键逐条核对，把部分失败和受过滤条目写进报告。合成回流按相同协议准备特征。[上游特征编排与索引](https://github.com/RVC-Boss/GPT-SoVITS/blob/20250422v4/webui.py)

## 5 训练控制与模型发布

| 操作 | 状态与产物 |
| --- | --- |
| 开始训练 | 创建运行，锁定数据与初始权重。两个阶段各自报告等待、运行、完成、跳过或失败。阶段完成后提交恢复点和推理快照，再交接到下一阶段。 |
| 暂停并保存 | 在当前阶段已支持的安全边界写入有效恢复点，成功后进入 `PAUSED` 并释放 GPU。等待时显示「正在保存」，写盘失败时报告最后可用点。 |
| 继续训练 | 从同一运行最后有效恢复点恢复正确的阶段、累计目标和优化器状态。服务或系统重启后可恢复。遇到恢复点缺失、损坏或配置不匹配时保留原运行并给出具体错误。 |
| 从历史恢复点派生 | 创建独立运行，记录父运行和恢复点。继承兼容配置并继续累计。选用新数据版本时从已发布权重发起新微调，重新初始化训练状态。 |
| 导出并继续训练 | 在安全边界冻结当前可用权重对，后台校验与发布，训练继续。使用尚未开始阶段的初始权重配对时，在版本卡上明确显示来源和进度。 |
| 中止并导出 | 保存当前运行的恢复点和模型快照，终止后续训练并发布有效权重对。用户可另行恢复或派生。 |
| 正常完成或重试导出 | 最后训练阶段达标后自动发布。失败可从同一不可变快照幂等重试，模型列表只展示完整注册的版本。 |

GPT 与 SoVITS 的恢复逻辑分别实现。保存各阶段权重、优化器、调度器、适用的精度状态、随机状态、采样器和游标，以及运行级阶段索引。P00 审计原生检查点，P06 补齐缺失状态。首个实测恢复边界按阶段公开，阶段内按步恢复以实测验证消费位置后开放。恢复索引和模型目录采用临时写入、校验及原子发布，保存失败时保护最后可用恢复点。恢复不得触发上游的静默底模初始化。[上游 SoVITS 恢复入口](https://github.com/RVC-Boss/GPT-SoVITS/blob/20250422v4/GPT_SoVITS/s2_train_v3_lora.py)

模型版本包含 GPT `.ckpt` 与 SoVITS v4 `.pth`，并记录各自的哈希和训练来源、共享资产依赖、参考素材、数据版本、导出原因与试听测试结果。上游格式的 SoVITS LoRA 权重随版本记录对应底模及 rank。结构校验和真实 GPU 试听独立记录。外部导入使用本地受信任权重，校验 GPT 与 SoVITS 的配对、v4 格式及 LoRA 依赖，可用后加入模型列表。来源模型作为新微调初值时，GPT 读入对应权重，SoVITS 以锁定底模和来源 LoRA 初始化。P11 验证初始化时只应用一次 LoRA，以及更换父模型后的实际起始参数。[上游 v4 LoRA 加载与合并](https://github.com/RVC-Boss/GPT-SoVITS/blob/20250422v4/GPT_SoVITS/TTS_infer_pack/TTS.py)

### 5.1 检查点写入和阶段交接

1. 控制命令按 `run_id`、阶段和 `request_id` 持久化。训练 worker 在优化器更新后的安全边界消费命令。处于梯度累积时，等当前累积周期结束，再确认暂停和导出。
2. 保存进度计数、已消费位置、调度器更新时机、RNG、优化器、scaler 与配置指纹。轮次边界签名标识下一轮开始。轮中恢复通过固定采样顺序和已消费游标定位，验证跳过样本与实际累计之间无重复扣减。记录已实测的恢复保证，逐样本确定性按实际测试报告。
3. 在同一卷写入临时恢复点，校验可读性和哈希后原子切换，再更新 `last` 索引。保留最近 3 个周期点作为初始策略。暂停点、阶段交接点、最终点及仍有引用的点单独保护。磁盘不足保留最后确认可恢复的版本。
4. 阶段结束先提交恢复点及推理快照，再推进活动阶段。若进程在两次写入间退出，重启时按交接记录补齐状态。若下一阶段已经创建实例，则根据实例记录和恢复点续训，以同一阶段 ID 避免重复启动。
5. 完整续训校验数据 fingerprint、阶段配置、底模、上游源码、LoRA rank 与剩余目标。配置变动时按历史点派生或权重初始化入口处理。应用将失败恢复点及最近有效点分别显示。

### 5.2 发布包的文件与可选状态

| 文件或状态 | 约定 |
| --- | --- |
| `gpt.ckpt` 与 `sovits.pth` | 适配层按上游加载协议产出，校验权重键、架构、版本和 LoRA 专用元数据。 |
| `manifest.json` | 记录包格式版本、角色、模型版本、GPT/S2 来源、哈希、依赖底模、声码器、默认参考及推理默认值。 |
| `training_summary.json` | 运行 ID、阶段完成量、停止原因、数据版本、冻结配置及来源模型。 |
| 参考素材、`preview.wav` | 参考素材以本机受管理文件或稳定引用登记，试听通过后保存可选预览和测试参数。 |
| 结构校验与 GPU 试听 | 结构校验通过后原子注册，GPU 试听单列 `NOT_RUN`、`PASSED`、`FAILED` 与原因。 |

导出先生成不可变快照，训练 worker 确认后继续。写包和 CPU 结构检查在有界队列处理，对主内存和暂存磁盘施加背压。GPU 试听通过同一租约队列。训练继续时，导出失败只影响对应导出记录。已完成或提前终止的运行可从原快照重试发布，幂等键固定同一模型版本。

## 6 本地合成、保存和句子回流

### 6.1 合成与播放

开启模型时检查权重对、资产和默认参考。推理 worker 可以在 GPU 空闲时复用已加载实例，训练或其他独占 GPU 任务开始前释放。受理请求时冻结模型版本、参考文件哈希、参考文本、目标文本、语言和参数。用户更改页面输入后，已生成音频继续显示原请求的文本。

单句直接合成。多句输入先分句，在同一任务内保留每句的文本、稳定 ID 与独立 PCM 或经过验证的样本区间，再按顺序拼接为可播放的整段。播放器同步显示当前句，句列表可显式切换。上游进一步切分或批处理时校验回填顺序与边界。检查输出非静音、可完整解码且为原生 48 kHz，再发布到播放器。保存使用独立产物 ID，支持 Range 播放、下载与重启后读取。[v4 输出规格](https://github.com/RVC-Boss/GPT-SoVITS/blob/20250422v4/README.md#v4-release-notes)

无效的新请求保留当前结果。有效请求进入队列时更新当前结果指针，旧未保存音频在播放、保存或追加任务释放引用后回收。暂时锁定的 Windows 文件进入待清理队列。永久保存的语音有独立文件路径，可通过作品库删除。

### 6.2 将当前句加入数据集

1. **锁定音频与归属。** 点击「将当前句加入数据集」时提交 `tts_job_id`、`sentence_id` 和目标数据版本。服务端从成功结果的清单取得音频、文本、来源模型和哈希，并锁定源文件。单句结果自动选中。多句结果使用播放器指示或用户点选的一句。对本项目自训模型，默认使用该模型对应数据集的最新可用后继版本，并显示目标角色和版本。外部权重缺乏训练数据归属时，界面显示原因。
2. **执行数据整理。** 用与原始录音相同的音频质检、必要切分和格式适配处理无损音频。整句保留且与朗读内容一致时，直接使用生成当时的输入文本作为标注，跳过 ASR。只裁掉头尾静音仍可沿用整句文本。拆成多段时优先使用可靠的逐段文本对齐，无法对齐的片段逐段 ASR 或手工校对。试听发现漏读、重复或截断时，可纠正标注或排除片段。
3. **发布新版本。** 标记来源为合成语音，记录来源模型、推理任务、句子、音频哈希与标注来源。新句追加到训练集，验证集继续取父版本的真实留出片段。对同一个数据集串行提交或使用版本比较与重试，避免并发追加覆盖。去重后补齐新样本特征，原样本按缓存键复用。空结果、失败或取消时保留父版本，追加任务退出后按合成结果的生命周期管理音频。成功后才登记新版本。
4. **用新版本微调。** 成功后显示新增条数、有效时长和可训练状态。点击按钮跳到微调训练页并预选新版本与该句来源模型。配置中允许切回官方底模。启动后使用新数据、新运行和独立训练计数。

### 6.3 产物发布、保存和清理

- 合成任务的工作目录包含冻结请求、逐句文件或样本区间、实际种子、解码检查结果和合成音频。优先使用无损 WAV 作为播放和回流来源，MP3 仅在用户选择保存或下载对应格式时编码。
- 生成元数据包含输入句序、原文的字符区间、实际文本、音频起止样本及片段静音边界。即使正文里出现两次相同句子，`sentence_id` 仍各自唯一。追加去重使用来源任务与音频哈希，再比对目标数据集内的内容。
- 受理保存、播放或追加时获取文件引用。保存先生成并校验独立文件再登记作品。受理下一条生成、关闭播放器或取消任务时按引用释放。文件已清理的历史任务继续显示文本和状态，播放端点返回已失效。
- 删除先将无活跃引用文件移至受管理回收目录，再提交元数据变更。Windows 播放句柄阻止移动时登记待清理。进程重启后依据数据库记录与文件存在状态核对待清理项，禁止误把外部源文件当作临时文件。
- 作品库默认按创建时间倒序，时间相同时按作品 ID 排序。筛选变化时清除当前按钮选择。跨页删除记录确认时的作品集合和条数，明确返回成功、已删除或受引用保护的项目。

**产物与验收** 提交 `setup.ps1`、`assets.ps1`、`doctor.ps1`、依赖锁与资产锁，覆盖 A05–A07。

### P03 录音扫描、切分与标注

**产物与验收** 提交数据模块、标注界面、样本夹具和对账测试。覆盖中文路径、重名、损坏、静音、重复、ASR 失败和真实原始文件哈希，覆盖 A08–A13。

**产物与验收** 提交特征工具、配置映射和前端预检。测试缺特征补跑、改文本失效、数据集不足、参数无效及真实加载器读入。覆盖 A14–A17。

### P05 双阶段实际微调

**执行步骤**

## 8 API 与持久化契约

### 8.1 HTTP 接口建议

实现时可调整命名，同步 OpenAPI、前端与测试。异步提交返回任务 ID 与受理状态。客户端重试使用同一 `request_id`，同键对应不同请求时返回冲突。后台完成后通过快照或事件读取产物。

| 方法与路径 | 用途 | 请求及响应约定 |
| --- | --- | --- |
| `GET /api/health`、`GET /api/system/status` | 服务状态与资源 | 返回工作区、依赖、GPU 资源及模型启用或驻留状态。 |
| `GET/PUT /api/settings` | 数据根目录、设备与默认参数 | 校验路径和写入能力，活动任务保留已冻结配置。 |
| `POST /api/datasets/scan` | 扫描录音目录 | 源路径、角色、语言、是否递归。结果包含 `scan_id` 和逐文件报告。 |
| `POST /api/datasets/prepare` | 整理和 ASR | 采用扫描指纹、排除项和切分规则，返回含失败条目的标注草稿。 |
| `GET/PATCH /api/dataset-drafts/{id}` | 查看或改标注 | 使用草稿修订号和片段 ID。旧修订号更新返回冲突。 |
| `POST /api/dataset-drafts/{id}/publish` | 发布数据版本 | 校验修订号、每段标注、清单与音频哈希。返回数据版本和特征状态。 |
| `GET /api/datasets/{id}/versions`、`DELETE /api/dataset-versions/{id}` | 查询及管理数据版本 | 返回统计、谱系及受保护原因。删除操作验证引用与管理路径。 |
| `POST /api/dataset-versions/{id}/features` | 生成或补跑特征 | 返回待处理数、复用数、失败项与加载器检查。 |
| `POST /api/training/preflight` | 训练预检 | 返回各阶段实际有效配置、样本、批次和阻塞原因。 |
| `POST /api/training`、`GET /api/training/{id}` | 新建、查看训练 | 冻结数据、上游与初始权重，返回活动阶段和两段累计量。 |
| `POST /api/training/{id}/controls` | 暂停、继续、导出或中止并导出 | 使用动作枚举、`request_id` 与相应运行状态。报告受理、执行和落盘结果。 |
| `GET /api/training/{id}/checkpoints`、`POST /api/training/{id}/derive` | 查看恢复点与派生训练 | 返回兼容性、进度、保护原因。派生记录父运行与恢复点。 |
| `POST /api/exports/{id}/retry` | 重试发布 | 沿用原快照和版本 ID。 |
| `GET /api/models`、`POST /api/models/import` | 模型列表与导入 | 导入提供 GPT 与 SoVITS 两个本地路径及参考条件。列表区分结构、资产和 GPU 试听状态。 |
| `DELETE /api/models/{model_id}/{version_id}` | 删除指定模型版本 | 给出任务或派生运行引用。永久作品使用自己的文件与历史元数据。 |
| `POST /api/inference/enable`、`POST /api/inference/disable` | 模型和参考启用状态 | 绑定版本与参考 ID，返回逻辑启用和实际驻留状态。 |
| `POST /api/model-tests` | 固定条件试听 | 返回模型版本、请求快照与试听音频 ID。 |
| `POST /api/tts`、`GET /api/tts/{id}` | 合成和结果 | 接收正文、语言、断句和推理参数。返回当前版本、逐句样本区间和音频 ID。 |
| `POST /api/tts/{id}/save` | 保存作品 | 选择音频格式和可选标题，成功后返回独立作品 ID。 |
| `POST /api/tts/{id}/append` | 追加指定句子 | 使用 `sentence_id`、目标数据版本和幂等键，返回新版本、时长及特征状态。 |
| `GET /api/saved-speech`、`POST /api/saved-speech/delete` | 作品检索和批量删除 | 记录分页、筛选或确定的删除集合，返回逐条结果。 |
| `GET /api/audio/{id}` | 试听、播放和下载 | 使用受管理的产物 ID，返回媒体类型、Range 或失效状态。 |
| `GET /api/jobs/{id}`、`GET /api/jobs/{id}/events` | 任务快照与 SSE | 支持续读、心跳、最终结果和阶段错误。 |

### 8.2 运行与产物状态

| 对象 | 状态或阶段 | 状态转换条件 |
| --- | --- | --- |
| 训练运行 | `QUEUED`、`PREPARING`、`RUNNING`、`PAUSE_REQUESTED`、`CHECKPOINTING`、`PAUSED`、`RESUMING`、`STOP_REQUESTED`、`FINALIZING`、`COMPLETED`、`EARLY_COMPLETED`、`INTERRUPTED`、`FAILED` | 控制请求校验当前状态，恢复点确认后才到 `PAUSED`。最终训练和发布结果各自持久化。 |
| 训练阶段 | `PENDING`、`RUNNING`、`PAUSED`、`SKIPPED`、`COMPLETED`、`FAILED` | 每次只有一个活动阶段。已完成阶段的快照在恢复和下游失败时仍可供配对。 |
| 导出 | `QUEUED`、`SNAPSHOTTING`、`WRITING`、`VALIDATING`、`PUBLISHED`、`FAILED` | 导出独立建任务，`PUBLISHED` 表示文件与模型索引均可读。 |
| 合成 | `QUEUED`、`LOADING_MODEL`、`PREPARING_REFERENCE`、`SYNTHESIZING`、`ASSEMBLING`、`VALIDATING`、`COMPLETED`、`FAILED`、`CANCELLED` | 成功时写句子索引和最终音频并确认可解码。使用任务 ID 查询错误、重试或取消。 |
| 追加 | `QUEUED`、`PREPARING_AUDIO`、`LABELING`、`REVIEW_REQUIRED`、`FEATURIZING`、`PUBLISHED`、`FAILED`、`CANCELLED` | 对齐不确定时转草稿。提交新版本之前验证标注与特征完整性。 |
| 音频产物 | `TEMP`、`SAVING`、`SAVED`、`PURGE_PENDING`、`DELETED` | 按文件引用和已提交的元数据变更迁移，与任务结束状态独立。 |

事件至少带 `schema_version`、`event_seq`、`job_id`、`event_type`、`stage`、`timestamp` 与 `payload`。覆盖进度、训练指标、控制确认、恢复点提交、版本发布和错误。进度带真实计数单位、分子及已知的分母，未知总量时使用进行中状态。每个任务的事件按序保存，SSE 从 `Last-Event-ID` 后续读。UI 断线时先同步快照，再合并后续事件。数据库存 UTC，显示用本机时区。

错误至少包含 `code`、`message`、`stage`、`retryable` 与关联 ID。P01 统一错误结构。P03 起加入业务错误，如 `UNSUPPORTED_LANGUAGE`、`NO_TRAIN_BATCH`、`INSUFFICIENT_VRAM`、`CHECKPOINT_INVALID`、`MODEL_DEPENDENCY_MISSING`、`AUDIO_EXPIRED` 和 `VERSION_CONFLICT`。向 UI 返回可操作信息，长异常入本地轮转日志。

### 8.3 关键持久化记录

| 记录 | 关联字段 |
| --- | --- |
| 原始录音与片段 | 源文件、分组、源样本区间、素材哈希、整理音频路径、语言、标注来源与审核信息。 |
| 数据版本 | 数据集 ID、父版本、发布状态、统计、清单、fingerprint、特征索引及引用。 |
| 训练运行与阶段 | 运行 ID、父运行、冻结数据、配置和依赖，当前阶段、阶段目标、实际更新与控制状态。 |
| 恢复点与导出 | 所属阶段、优化器进度、哈希、兼容性、保护原因、快照和模型版本。 |
| 模型与参考素材 | 模型记录 GPT/S2 权重、版本和依赖，参考记录音频、文本、语言及哈希。合成请求保存所用版本与内容哈希。 |
| 合成、句子与作品 | 冻结合成参数、实际种子、输出与句子音频索引、临时或永久文件归属及播放状态。 |
| 追加记录 | 源任务、`sentence_id`、来源模型、目标父版本、音频和文本哈希、新版本 ID。 |

文件记录使用应用管理区内的相对路径。解析实际路径、确认目录归属和引用后才移动或清理。比较路径时处理 Windows junction、符号链接与大小写，SQLite 事务关联同一版本的多条记录。跨数据库与文件系统的中断由启动对账处理。

## 9 WebUI 操作细节

### 9.1 微调训练页

1. **录音数据区** 先选目录、角色和语言，再扫描或整理。扫描报告显示各文件可用状态、时长与试听。手动排除、切分与 ASR 改动显示在整理任务快照。
2. **标注草稿区** 提供片段列表、音频播放、转写编辑、语言选择、重识别和排除。发布时提示还需要处理的片段。不同录音目录和不同角色的草稿使用明确标题。
3. **数据版本和训练区** 提供准备特征、补跑、初始化模型、分阶段常用和高级参数。预检结果并排显示 S1、S2 的实际参数与阻塞原因。可启动后继续沿用原按钮位置。
4. **后台任务和版本管理** 选中运行后展示当前阶段、两段进度、loss、学习率、速度和实际显存。暂停时分别显示等待安全边界和写入恢复点。导出状态独立展示。恢复点列表提供继续或派生，模型版本列表提供试听及可用时删除。删除数据前显示所属角色、版本和引用情况。
5. **模型效果测试** 选择版本 A 和 B，填写固定短句及共用参考，播放两份 TTS 结果。显示生成参数、实际种子、版本和参考来源。

### 9.2 语音合成页

1. **模型与参考区** 模型卡展示本项目已注册版本及来源，外部导入入口选择权重对。可试听参考、设置参考语言、编辑参考文本与开启模型。状态显示可提交、排队或加载失败的具体原因。
2. **合成区** 常用控件包括文本、目标语言、语速和开始按钮。断句与采样折叠在高级区。输入修改只影响下一条请求，播放器显示现有任务的冻结文本。
3. **当前结果区** 支持整段播放与跳到某一句。默认单句直接选中，多句可跟随播放位置或手动切换。「将当前句加入数据集」显示目标角色和句子文本，无需划取时间。若进入校对，提交后继续原追加任务。
4. **已保存语音区** 默认显示最近 10 条，可按模型、标题和正文筛选、下载、批量选择和删除。确认框提示影响本页还是跨页筛选结果。返回上一页和刷新可重新读取保存状态。
