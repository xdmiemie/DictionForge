# P09 合成受理、坐标与产物服务验收

本页记录 `text_units.py` / `synthesis.py` 的 CPU 合同与真实音频文件 I/O 测试。测试使用明确标记的假模型字节及合成 PCM 波形，不加载模型、不占用 GPU，不冒充语音质量、ASR 或试听验收。真实 GPU 产物见本阶段主验收报告及 `P09_WORKER.md`。

## 冻结和坐标合同

- `POST /api/tts` 受理前验证文本、普通话语言标记、分句规则、推理参数、模型权重及参考哈希。纯空白、纯标点、纯 emoji、非法控制符及不支持的参数均明确拒绝；失败不改变当前结果指针。
- 数据库同一写事务冻结 `tts` 请求和 `tts_current/current` 指针，重新核对模型、参考媒体可用性。相同请求 ID / 输入重放返回原任务，不把当前指针移回旧任务；同请求 ID 的不同输入拒绝。
- 原文以 `text` / `source_text` 原样保存。标点、按行、不分句三规则生成应用单元；每句仅裁去其边缘空白，`text == source_text[source_start:source_end]`，坐标为 Unicode code point 半开区间。重复正文仍有不同、稳定的句 ID，索引从 0 开始。
- `seed=(base_seed+index)%2**32`；整数位置、种子、样本数等字段拒绝 bool。显式参考可覆盖失效的模型默认参考，但仍须单独通过参考验证。
- worker 的 `normalized_texts` 是真实目标文本前端返回列表，`actual_text` 是该列表顺序连接。服务保留这些字段和原文坐标；不把规范文本宣称为 ASR 转写，也不声称字词时间对齐。

## 发布与取消的边界

- worker 请求 / 结果位于 `data/runtime/tts/<job_id>/`，进程日志位于 `data/runs/<job_id>/process.log`。结果必须完整解码为 48 kHz、单声道 PCM16 WAV，核对路径在任务管理目录、文件大小、SHA-256、时长、样本数、句序及源区间。
- 每句 PCM 与完整音频对应的半开样本区间逐样本一致；完整文件必须恰好为各句连接。没有服务侧重采样、剪裁或句间静音插入。解码后再次检查句文件与全段哈希，媒体登记时再检查实际哈希。
- 首尾静音观测阈值为 `{amplitude:32,unit:'pcm16'}`；有效信号条件 `abs(int32(pcm))>32`，全句不超过阈值则拒绝。错误明确带出验证阶段；涉及句字段的错误带句索引 / ID。
- 全部产物验证成功后，同一 SQLite 写事务登记全段和逐句媒体、写 `tts_result`、发出 `tts_ready`。事务提交是可用结果的发布点；任一句失败不会登记部分媒体。任务失败 / 取消时当前指针仍指向本次已受理任务，旧任务和文件保留，不进行 P10 清理或保存。
- 取消在推理前、子进程结束后再次检查，并在发布写事务内最后复核。该写锁与取消受理写锁串行：取消先提交则不发布；结果发布先提交则保留已完成结果。之后才到达的取消由 worker 的终态 control receipt 说明任务已完成。后者的完整 HTTP 时序实测留给后续阶段；本阶段没有把未执行场景标为通过。
- 完成结果重入不会再次推理或重复登记媒体；若已有产物在之后被外部改坏，重验写 `FAILED / result_revalidation`，不继续展示可用完成结果。

## 引用保护

- 活跃 TTS 任务冻结来源模型及参考。即使替换模型默认参考，原请求使用的数据版本仍受删除保护。
- 完成结果保存来源模型、角色、来源数据版本、参考 ID / SHA-256 和请求 ID。保留结果对来源模型的依赖，留待后续清理策略显式释放。本阶段不实现作品库、回收或追加数据集。
